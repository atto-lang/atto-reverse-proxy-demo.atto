# Staged typed HTTP header names

Both native Oreslang proxy repos intentionally carry the same local
`src/header_policy.ores` implementation until a **verified** shared
Oreslang HTTP standard-library module and cross-repo dependency contract exist.
Do not assume two source copies are a published, shared stdlib.

The module now declares a closed nominal `HeaderName` enum. It maps known,
already-canonical lowercase header keys to enum cases once for policy checks.
`Other` is a sentinel, **not** a serialized header name or string payload;
the caller still retains the validated raw key for extension headers and for
exact membership in the dynamic `Connection` nominated-name list.

The policy keeps separate groups for:
- Fixed hop-by-hop / legacy connection fields.
- `Proxy-Authenticate` and `Proxy-Authorization`, whose protocol behavior
  is direction- and trust-dependent. This conservative proxy copy helper drops
  them; it is not a general HTTP authentication implementation.
- Request-only sensitive / synthesized fields.
- Response framing fields regenerated by the future HTTP adapter.
- Response `Content-Encoding` and `Content-Range`, which cannot be
  safely suppressed without understanding/transforming the body.

Existing public `request_copy`, `response_copy` and `response_action`
interfaces still accept canonical strings and preserve their earlier
conservative decisions. Unrecognized valid header keys are allowed unless
nominated by `Connection`. A case-insensitive raw-header parser must validate,
normalize and reject malformed/ambiguous wire framing **before** using these
helpers; the module itself is not a complete HTTP parser.

## Release gates

- This enum change is **staged**, not compiler-proven: nominal enum parsing,
  execution, import/export identity and LLVM/Graal parity remain under
  development in the compiler repos. Keep proxy PRs draft until exact-head
  `oreslang --check` and native Oreslang tests pass on the approved runner.
- Contract sources: `tests/header_policy_contract.ores` and
  `tests/header_enum_contract.ores`, both checked and executed from the
  exact-head native-contracts workflow.
- Do not deploy HTTP forwarding solely because header classification passes.
  Request smuggling, duplicate fields, HTTP/2 semantics, WebSocket upgrades,
  auth, transport lifecycle, streaming bodies and trailers need integration
  tests and authoritative framing enforcement.
- Once the typed `std.http.HeaderName` module is available, replace the two
  local definitions with imports and add cross-backend consumer tests, rather
  than exposing conflicting nominal types at module boundaries.
