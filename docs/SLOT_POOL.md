# Pool-level admission and bounded reclamation

The Oreslang `slot_pool.ores` and `tests/slot_pool_contract.ores` extend the one-slot lifecycle proof to a capacity-bounded collection. Up to 1,024 slots (the current parsed in-flight budget) may be OPEN/RETIRING simultaneously. Every admission gets both a per-slot incarnation+epoch and a **pool-global nonce**, so per-slot claim serial collisions cannot cause cross-slot cancellation or completion. The pool rejects admission when all slots are OPEN or waiting for in-flight claim drain. A closed slot with live receipts cannot be allocated until those receipts settle. The test includes two occupied slots, cancellation while pinned, backpressure, forged cross-slot receipt, duplicate/late completion and recycling.

**Important:** this is a persistent immutable reference model: `replaced()` copies every slot and nonce on an update and each per-slot transition copies its pending list. It intentionally proves ordering and identity, not performance, zero allocations or concurrency. Do not wire it into an HTTP handler. The implementation still needs actor-owned fixed-capacity primitive columns, a bounded free list, small-vector pin receipts, release barriers, scheduler and socket admission, and a real HTTP exchange API. The exact-head cross-backend compiler gate is still unexecuted.

Pool-global nonces cannot be used as cryptographic authorization; internal actor-owned handles must also obey compiler-enforced ownership and capability boundaries. External strings/network data must never supply trusted pool IDs. All request routing must be normalized/canonicalized before admission.
